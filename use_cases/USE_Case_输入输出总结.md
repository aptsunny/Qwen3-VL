# Qwen3-VL USE Case 输入输出总结

## 📋 重要说明

> **⚠️ 本文档中的 USE Case 仅用于量化流程和精度影响的研究参考，不代表实际业务部署场景。**
>
> 这些 case 的目的是：
> 1. 帮助识别和解决量化过程中的技术痛点
> 2. 提供不同任务类型的量化难度评估
> 3. 验证量化方案对模型精度的影响
>
> **不作为**直接部署的业务场景推荐，实际业务需根据具体需求调整。

## 文档说明

本文档总结了 Qwen3-VL-2B 和 Qwen3-VL-4B 模型在各种 USE Case 下的实际输入输出，旨在为高通芯片部署提供清晰的**量化精度基准参考**。

**测试环境**：
- GPU: NVIDIA H800
- 模型精度: FP16 (Auto)
- 测试日期: 2026-04-28

## 二、详细输入输出对比

### Case-01: OCR (英文)

**输入**：
- 图像：饮料瓶标签
- Prompt: `Extract all text from this image.`
- Input tokens: 4,349

**输出对比**：

| 模型 | 输出 |
|------|------|
| **2B** | `a product of The Coca-Cola Company<br>LATIN BIORHYTHM MATE<br>태양의<br>마테차<br>PLAY! EAT! DRINK MATE<br>b` |
| **4B** | `a product of The Coca-Cola Company<br>LATIN BIORHYTHM MATE<br>태양의<br>마테차<br>PLAY! EAT! DRINK MATE` |

**量化难点分析**：
- ✅ **低难度**：OCR 任务对量化相对鲁棒
- Vision W8A16 + LLM W4A16 即可满足精度要求
- 注意：输出末尾字符可能有微小差异（2B 多输出 "b"）

### Case-02: OCR (中文/多语言)

**输入**：
- 图像：马来西亚发票
- Prompt: `识别图片中的所有文字。`
- Input tokens: 1,204

**输出对比**：

| 模型 | 输出摘要 |
|------|---------|
| **2B** | 完整识别发票内容，包含：公司名、地址、发票号、商品明细、金额等 |
| **4B** | 完整识别发票内容，格式更清晰，包含底部二维码编号 "A06002" |

**量化难点分析**：
- ✅ **低难度**：多语言 OCR 对量化相对鲁棒
- 4B 输出格式更规范，识别更完整

---

### Case-03: 物体识别 (Omni Recognition)

**输入**：
- 图像：餐桌上的多道菜品
- Prompt: `Identify all objects in this image.`
- Input tokens: 11,862

**输出对比**：

| 模型 | 输出摘要 |
|------|---------|
| **2B** | 列出 7 个碗及内容：米饭、汤、橙子、卷心菜、番茄炒蛋、辣子鸡等 |
| **4B** | 详细分类列出：食品（6类）、餐具（碗等），描述更详细 |

**量化难点分析**：
- ✅ **低难度**：物体识别对量化相对鲁棒
- 4B 输出结构更清晰，分类更准确

---

### Case-04: 2D Grounding (目标定位) ⚠️ 高量化难度

**输入**：
- 图像：餐桌俯视图
- Prompt: `Locate all objects on the table and provide their bounding boxes in JSON format with relative coordinates (0-1000).`
- Input tokens: 2,736

**输出对比**：

| 模型 | 输出 |
|------|------|
| **2B** | `[{\"bbox_2d\": [0, 47, 1000, 1000], \"label\": \"objects on the table\"}]` |
| **4B** | `[{\"bbox_2d\": [0, 104, 204, 486], \"label\": \"bowl\"}, {\"bbox_2d\": [256, 83, 333, 227], \"label\": \"bowl\"}, ...]` |

**⚠️ 量化难点分析**：
- **高难度**：坐标精度对量化高度敏感
- 2B 输出过于笼统（只有一个大框），4B 输出更精确（多个小框）
- **量化后预期问题**：
  - 坐标值可能偏移 5-10 个单位
  - 小目标可能被遗漏
  - 建议保留输出层为 FP16

**量化建议**：
```
Vision: W8A16（避免 W8A8）
LLM: W4A16 + LPBQ
输出层: FP16
```

---

### Case-05: 文档解析 (Document Parsing) ⚠️ 高量化难度

**输入**：
- 图像：学术论文表格
- Prompt: `Parse this document and output the structure in JSON format.`
- Input tokens: 8,601

**输出对比**：

| 模型 | 输出 |
|------|------|
| **2B** | JSON 结构，包含表格标题、列名、多行数据 |
| **4B** | JSON 结构更完整，包含 sections 分组（General/Math/Coding/Multilingual） |

**⚠️ 量化难点分析**：
- **高难度**：结构化输出对量化敏感
- 长序列（8K+ tokens）推理，KV Cache 压力大
- **量化后预期问题**：
  - JSON 格式可能不完整
  - 数值精度可能下降
  - 建议使用 KV8 减少内存

| **4B** | 详细描述两把椅子的具体位置、隔断墙、地毯图案等 |

**量化难点分析**：
- ⭐⭐⭐ **中等难度**：空间关系推理对量化有一定敏感度
- 4B 输出更详细，空间描述更准确

## 三、量化难度分级总结

### 3.1 难度分级标准

| 等级 | 标识 | 特征 | 量化后预期精度损失 |
|------|------|------|------------------|
| **低** | ⭐⭐ | 单图推理，输出为自然语言描述 | < 1% |
| **中** | ⭐⭐⭐ | 结构化输出，空间推理 | 1-2% |
| **高** | ⭐⭐⭐⭐ | 坐标输出，长序列 | 2-3% |
| **极高** | ⭐⭐⭐⭐⭐ | 视频输入，时序一致性 | 3-5% |

### 3.2 各任务量化建议

| 任务类型 | Vision 量化 | LLM 量化 | KV Cache | 特殊处理 |
|---------|------------|---------|----------|---------|
| OCR | W8A16 | W4A16 | KV8 | 无 |
| 物体识别 | W8A16 | W4A16 | KV8 | 无 |
| **2D Grounding** | **W8A16** | **W4A16+LPBQ** | **KV8** | **输出层 FP16** |
| 文档解析 | W8A16 | W4A16 | KV8 | 长序列分段处理 |
| 空间理解 | W8A16 | W4A16 | KV8 | 无 |
